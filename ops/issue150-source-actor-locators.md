# 原文抽出の主語引用を構造化する

主語・経路のモードを表す `m.u` の各引用は、プロバイダー向けには
`{first,last,quote,focus}` とする。`first`/`last` は元の節番号、`quote`
はその範囲の原文、`focus` は `null` またはその原文内の一意な部分文字列。
たとえば `[{first:0,last:0,quote:"制御器は",focus:"制御器"}]`。
主語を引用できない既存の受動事実等の `u:null` は引き続き扱う。

単なる文字列が通るスキーマでは、引用構文に合わない文字列も生成制約を
通過できる。Azure Structured Outputs は文字列の `pattern` をサポート
しないため、数値と原文を別の必須フィールドにした。番号は128節以下では
実在する節番号の enum、より大きな入力では整数型と既存の範囲検査を使う。
これは節数の新たな上限ではない。

受信側はモデルが選んだ表現を既存の `first-last:quote`／
`{reference,focus}` に可逆変換するだけで、主語や欠落条件を補わない。
節範囲・12節幅・文字数・原文一致・一意性・意味・全体網羅性は既存の
検証器が引き続き検査する。既存の正当な文字列・focus形式も内部の受信
境界で維持する。監査にはモデルから受信した構造をそのまま残す。

型付き引用の4プロパティで既存の100プロパティ制限を超える入力は、
従来の引用生成スキーマと例を保持する。構文補助の追加によって既存の
対応入力を拒否しないための互換処理であり、この場合の生成文字列には
従来どおり後段の厳格検証が必要となる。通常例の主語・所有者・継続する
制御装置の説明は system の既存例に残し、同じ内容の schema 説明の重複を
除いた。経路モードの説明は区別して保持する。

保持済み3公報の入力による隔離計算では、6抽出＋生成＋独立レビューの
最大8送信は不変。スキーマを含む既存の予約式で、既存の当日枠内を
維持する。出力トークン上限は変更しない。具体額は非公開の検証記録に残す。
これはローカルの構文・互換性・予約額の確認であり、将来のモデル応答の
意味的な成功を証明するものではない。原応答を修復して再利用しない。

仕様根拠: [Azure Structured Outputs](https://learn.microsoft.com/en-us/azure/foundry/openai/how-to/structured-outputs)
の必須フィールド、100プロパティ／深さ5、および非対応の文字列制約。
