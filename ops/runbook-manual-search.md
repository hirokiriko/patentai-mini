# Runbook: Manual Search with J-PlatPat

## この Runbook の役割
請求項抽出・検索式生成・先行文献スクリーニング・詳細比較のAI呼出しは、
各試行の出力を8,192 tokensまでに制限する。この上限は当該4処理の全providerに
適用され、再試行時も維持される。上限で出力が途切れた場合も既存のfallback／
エラー処理を使い、fallbackを実AI成功と扱わない。入力量、モデル単価、再試行・
実行回数による総費用は別途確認する。外部J-PlatPatの手動工程は維持する。

J-PlatPat は無料で提供される特許情報検索サービスです。citeturn0search1turn2search11
本 PoC ではここを**人間が操作する外部工程**として扱います。

## Issue #86の今回限定検証

`LOCAL_AUTONOMOUS_EXECUTION_V2`では、公開・架空TXTから作る新規案件で
本サービスの実DB・実AI・実画面をLocal Codexが検証する。J-PlatPat検索の
自動操作、顧客・実案件dataの受入れ、公報投入は対象外とする。この外部検索
工程のユーザー操作を今回の完了条件に追加せず、本サービス内の検証成功を
J-PlatPat調査完了と扱わない。秘密境界、回数・費用上限、対象限定cleanupと
実測による完了判定は、`AGENTS.md`の今回限定規則とIssue #86本文に従う。

## 手順
1. システムで生成された `broad / balanced / narrow` の検索式を確認する
2. J-PlatPat の「特許・実用新案検索」で検索する
3. 必要に応じて検索条件を微修正する
4. 検索結果を CSV 出力する
5. CSV を本サービスへ再アップロードする

## 運用上の注意
- CSV 出力の利用には申請・ログインが必要な手順がある。ログイン後、画面右下に CSV ダウンロードボタンが表示される。citeturn2search0
- 特許・実用新案検索では、検索結果の CSV 出力件数上限が 500 件から 3,000 件に拡張された案内がある。citeturn2search4
- 検索結果が 500 件以下の場合、要約を含めた CSV 出力が可能と操作マニュアルに記載がある。citeturn2search0

## PoC で最低限欲しい持ち帰り物
- 検索結果 CSV
- 使った検索式
- 必要なら重要文献の PDF

- 何件ヒットしたか

- CSV が何件取れたか

## 出願後watch結果を読むとき

watch一覧・単一実行・期間レポートの「AI比較の範囲」は、表示中にai候補がある場合の現行比較方式の説明である。自案の独立請求項（抽出できない場合は全請求項）と、公報の要約および請求項テキストの先頭最大2,000文字を使う。明細書全文やそれを超える請求項は比較範囲外なので、差分候補を公報全体の不存在と解釈せず、Lowでも原文を確認する。

各保存結果の実送信文字数・切断有無の実測記録ではない。fallbackだけ・候補0件の表示にはこの注記を出さず、混在時もfallbackをAI詳細比較済みと扱わない。印刷にも同じ注記を残す。既存CSVの列・値は変わらない。

## なぜ記録が必要か
複数セッション開発では、検索過程を残さないと「なぜこの文献が候補に入ったのか」が再現不能になります。これは取りこぼしの温床です。

## 公報更新から監視帳票まで（Issue #125）

1. 対象の公報発行期間と手動取得物を、既存の定例checker/取込記録で照合する。不足・要確認・未解析添付を残す。2号の実証を期間全体の網羅と扱わない。取得/通知は自動化していない。
2. 既存の取込結果でinserted/reused/failed/unknownを分ける。同bytes再利用で先行保存や更新時刻を変えず、結果不明は同じ操作を盲目的に再送しない。Jobの消費枠は別管理。
3. 比較資料と監視開始日を確認して明示的に監視する。再読込はGETだけであり、監視POSTを追加しない。候補あり、正常0、新規なし、fallback、failed、結果不明を区別する。
4. 候補の書誌・番号から原文へ進み、構成の一致/差分と入力範囲を確認する。AI入力は独立請求項と公報要約/請求項先頭最大2,000文字であり、全文の不存在を証明しない。確認状態を変更したら再読込で保存を確かめる。
5. 完了runのCSV（14列）と、監視開始日のJST期間（最大31日）を指定した期間HTMLを取得する。印刷ボタンからPDFを保存し、全ページの番号・件数・期間・確認状態・入力範囲/法的注意文をCSV/HTMLと照合する。CSVの `reviewed` は画面の「確認済み」に対応する。失敗runのCSV409は正常拒否で、失敗混在の期間reportは不完全と表示する。
6. 保護停止時は再送せず、当該POSTのdiagnosticを保全する。detailの任意観測があればphase、実件数、完成POST bytes、attemptと3種elapsedを同じidで確認する。観測欠損はUNKNOWN。awaiting_responseだけではprovider/通信の原因を特定できず、usage不明の予約を解放しない。結果不明の照合は既知対象のGETに限定し、同じ論理read最大3回、未知writeは再送しない。
7. 試験終了時は対象を固定した案件/添付だけを回収し、削除ACK・添付cleanup・case404を別々に照合する。成功公報、先行証拠、費用台帳、次回用の既存Job/必要権限は保持する。

専門家の評価、顧客利用、期間網羅、元の遅延原因、物理PC停止は未確認として保持する。rollbackは変更commitのrevert PRと既存通常deploy。公報削除、cursor巻戻し、モデル/入力/guard緩和で成功を作らない。
