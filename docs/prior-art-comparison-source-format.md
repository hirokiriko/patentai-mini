# 比較原文の可逆な抽出形式

原文の引用と意味を別々に検証する。引用の位置が正しくても、主体、否定、条件、
経路、選択関係が正しいとは限らない。実AIの品質判定には原文との照合が必要である。

現在の実行入口は請求項単位のv24である。比較全体から対象と参照先を含む抽出計画を
送信前に固定し、各要求には同じ文献の未改変の原文・参照関係・比較範囲を保持する。
回答対象だけをsource digestと請求項番号の組で限定する。請求項の一部分を独立した
公報として再計画せず、元の引用座標、参照関係、loop番号を維持する。

各回答は対象請求項のQ・facts・動作対応キー・所属loopだけを含む。欠落、重複、別請求項の引用、
未宣言Q、原文順の逆転、根拠の範囲外、意味の未抽出を受信時に検査する。処理は直列で、
失敗後は次の要求を送らない。全回答の成立後も元の完全なv22検証・復号・原文QAを
適用する。結合時に引用、順序、条件や主体を補修しない。旧不合格回答は検証記録として
保持するだけで、新しい実行の入力や成功結果として採用しない。

v24のQは `{id,K:[開始行,開始列,終了行,終了列]}` で、元のUnicodeセルを両端含みで
選択する。モデルに引用文字列と句範囲を別々に生成させない。選択した位置から原文引用と
所属句範囲を復号し、反復語の識別に必要な隣接原文だけを既存形式へ符号化する。
選択位置の変更・別位置への近似探索・句順変更・回答の意味補完は行わない。
不正座標、重複ID/位置、未使用引用、12句を超える証拠、80文字を超える用語は拒否する。
64,000 bytesは受信回答だけでなく結合後の既存形式にも適用する。符号化で膨張した場合も
この上限を超えて採用しない。

原文から列挙した動作出現の `t0,t1,...` はschemaの必須整数キーである。値は当該claimの
facts内の番号であり、その実factの動作・述語・極性・引用位置が元の出現に一致する必要がある。
別の定義動作・経路・長い演算子引用・空factsによる代替を拒否する。同じfactが複数項目を
満たす場合もそれぞれの出現に実一致しなければならず、番号合わせの重複factや並べ替えはしない。
明示的なモード経路内の完了減圧、能動の切替実行と維持も狭い原文パターンで検査する。
一般の条件文・否定文から肯定動作を生成しない。維持はa/Jで同じ完全状態と維持動詞を保持する。
この部分的な動作一覧は正解表ではなく、主体・目的語・条件・文脈はモデルが抽出する。
一覧にない意味と従属参照も含む原文QA、既存の句被覆・意味・domain検証は全て必要である。

上限は参照先を含め19請求項、通常比較は抽出N件＋比較1件＋レビュー1件で最大21送信。
対象と段階を予算スコープに束縛し、同時送信、段階の取り違え、追加再送を拒否する。
通常処理は最大75分、診断は独立した原文QA待ちの固定15分を別に確保する。
1要求のタイムアウト・token上限、全体の64,000 bytes、原文ごとの96命題上限は維持する。
予約額はこの上限から有限実行ごとに計測し、承認済みの実行束縛なしに送信しない。

HTTP入口は永続予約のCOMMIT ACK後に202を返し、同じサーバープロセスのafter処理で
抽出から保存まで実行する。画面は保存状態だけを照会し、再読込・再接続・同一POSTで
AIを再実行しない。予約能力は1回だけ消費でき、サーバー再起動時の未完了予約も自動で
復活させない。既知の品質FAILは停止段階と種別を保存して表示する。通信・usage・
書込ACKが不明なら未確認予約を保持し、品質FAILや精算済みに読み替えない。

after処理は耐障害キューではない。配備時は常設クラウドの稼働レプリカ、実行中の
再配備・再起動防止を確認する。保存後の再起動読込、PDF全ページ、CSV全セル、再取得時
AI送信0件、PC停止中の固定URL利用は、それぞれ実環境で確認して初めて成立とする。
本番の原文QAには、OWNER限定の `GET /api/cases/{caseId}/analyze/{operationId}/source-audit`
を使う。既存比較予約行のprivate sidecarへ、全請求項のSDK構造化回答を無補修で保存し、
COMMIT ACK後だけ比較生成へ進む。抽出失敗時は取得済み回答とSDKの失敗テキストを保存する。
監査保存のACK不明時は後続AIを停止し、再送しない。上限超過したテキストも切り捨てて
成功扱いにはしない。監査JSONは2,500,000 bytes以内、失敗テキストは1,000,000 bytes以内。
通常の保存v1・PDF/CSVには監査原応答を混ぜず、GETはOWNER認証・no-storeで取得のみ行う。
読み出し時も操作、入力digest、全タスク順序、全所有行の同一性を検証し、完成結果では
保存済み原本から計画を再構成して照合する。構造化回答はHTTP envelopeのバイト同一保存ではない。
usage・HTTPの証跡、独立原文QA、PC物理停止中の別端末利用確認は別途実測する。
以下には引用・意味表現の各版と、変更せず継承している検証を記載する。

source wire v17は、既存の原文分割から得た完全句を `[句ID, 原文]` の順序付き一覧で
渡す。連結すると全文に一致し、従属参照も保持する。AIは文字位置や行列座標を計算せず、
意味の各役割を短い原文引用で指定する。各命題のWで指定した根拠内の一意な完全一致だけを
原文のUTF-16位置へ戻す。反復時は厳密な `{quote,before,after}` で隣接原文を明示する。
contextは位置の識別だけに使い、Wの根拠には加算しない。句IDを全役割に重複指定させない。
短い引用の転記は残る。別請求項への探索、正規化、引用の修復、近い一致への移動はしない。

各命題のWは根拠となる完全な入力句を指定する。全ての用語と明示的な演算子・経路の
引用がその範囲に入ることを検査する。Wは句IDの明示選択で、旧Y対応表はコードで逆引き
する。未被覆句、未抽出説明、非loop請求項の空配列、不確実な命題による穴埋めを拒否する。
句は読取単位であり意味の単位とは限らない。後置主体・完全条件・依存末尾も読む。
演算子・frameは連続完全句のID群、または指定句範囲内の一意な原文引用を使う。
非連続句を勝手に包絡しない。Oは常に5項目で、条件・否定等の必要なproofを要求する。
v17のOは必須5フィールドのobjectである。空proofや文字列だけの配列は拒否する。
旧v15/16の明示入口だけに従来形式を保持する。
loopが回答済みでも、それ以外のモード、条件、作用、配置等が残る請求項を空配列にしない。
Wの全句対応でも抽出の意味品質は証明できない。主体・条件・否定・経路・従属参照・
必要な命題は独立した原文QAで確認し、全件対応だけでは合格としない。

v17の意味enumは可読名を要求し、内部enumへ可逆に変換する。各relationは動作の
原文引用aを持つ。引用の配列とcontext tupleの曖昧さ、数値述語の取り違えを減らす。
旧形式のprovider schemaでは配列の説明だけに頼り、余分な配列階層や単項proofを
構造で禁止できなかった。v17はobject・required・additionalPropertiesで区別する。
Azure非対応のminItems/maxItemsへ依存せず、Wの1〜12件や連続句を実行時にも検査する。
対応する制約は[Azure公式仕様](https://learn.microsoft.com/en-us/azure/foundry/openai/how-to/structured-outputs)を参照。

新形式の上限は1原文96命題・1024引用、全source wire 64,000 UTF-8 bytesである。
既定原文の基礎側は、同一主体等の並列対象をまとめても必要命題の下限が51件あり、
旧48件では完全な抽出を表現できなかった。容量は受理の意味基準ではない。
旧入口の48命題・512引用・32,000 bytesは維持する。
旧v14の厳密な位置・根拠検査とv13の原文照合を内部で再利用する。旧形式の明示入口は
過去回答の再生・互換テスト用として保持する。
新しい実行で旧応答を修復して受理することはしない。

復号後は従来の厳密schema、請求項・sourceの一致、完全claimのbasis、80文字のterm、
guardの包含、演算子の根拠、必須閉路などを検証する。全件を不確実にしたり、
必要な命題を省略したりすることで容量を満たしてはならない。

同時開動作、いずれか一方の開動作、実行、停止、受動的な給電終了を区別する。
給電終了では根拠のない遮断主体を補わない。これらの述語を一般的な開動作や集合所属へ
読み替えず、条件・否定・参照関係についても既存の保守的な比較を維持する。
生成指示には条件付き維持動作の短い架空例を含め、主体・条件・維持状態・独立した
各句の根拠指定を既存decoderで検証する。複雑さだけを理由に請求項全体を未抽出にしない。
熱作用の対象は部材であり動詞ではない。通電条件はguardに保持し、ORをANDに変換しない。
主体・条件・否定・述語が同一の並列対象だけをまとめる。
件数や容量のために必要な意味を落とすことは認めない。

コードは原文中の閉動作・熱作用の限定的な動詞と、句境界が明示された時点のOR一覧を
読取チェックリストとして渡す。意味の主体や対象は自動生成しない。閉弁をstopsとする
不一致、独立した放熱/吸熱の欠落、認識できたORのAND化・分岐欠落を拒否する。
閉状態の維持、明示否定、能力と実運転は区別する。この検査は一般文法の解析や
全意味の証明ではなく、主体・全対象・完全条件・否定・経路・従属参照の原文QAは必須である。

実行内witness v2は、同じ意味の接頭部と位置情報の重複を減らす。元の順序、claim番号、
全bindings、operators、routeFrameをv1へ完全復元できる。v1の展開も保持し、
再符号化が一致しない余分な辞書や非標準のtupleは拒否する。内部上限は32,000 bytes。

target入力のdescriptor v2は主語とbasisの辞書を使用する。各行のID、claim番号、
basis、kind、subjectを損失なく復元でき、上限12,000 bytes。
target回答のv1、保存結果のv1、再表示・PDF・CSVの読込形式は変更しない。

Azure sourceのlow出力上限は32,400 tokens、入力のアプリ上限は120,000 bytes。
段別の実行上限・予約は別途有限実行に束縛する。終了済み枠を再利用せず、実測と
最新台帳から新規承認・署名を成立させるまで追加AIを送信しない。既存の失敗回答は
未改変で保全し、形式変換したものを実AI合格と扱わない。

比較の利用量は、検証済みの比較operation ID・段階・入力/出力tokensだけをログへ記録する。
原文・生成内容・案件名・認証情報を含めない。ログが取得できない場合、利用量を0とみなさない。

架空入力の往復・境界・統合テストは接続と容量の確認であり、実AI品質の合格や
本番での利用確認を代替しない。

v20は各cNを原文句数と同じ行数の命題配列にし、原文順の読取りを要求する。
各命題は所属行に重なる実際の意味引用を持つ。空行や行の被覆は意味の完全性を
証明しない。通常引用は単一句でも`first-last:原文`とし、複数句の連続引用と
区別のない位置指定を使う。曖昧な同文は従来の前後文脈objectで特定する。
Oは実際の演算子の引用かnullだけを認め、裸の範囲指定で広い文脈を代用しない。
Fの明示的な経路範囲と1命題12句の上限は維持する。

部品の圧縮・減圧・加熱・冷却・検出・出力・流通の明記された機能も、限定的な
動詞チェックに加える。名詞や条件の前提から肯定動作を作らず、主体・対象・条件を
自動補完しない。維持動作のaは維持される状態と「維持」を含む。
旧v17〜v19の検証入口と原応答を保持し、新形式への修復による受理は行わない。

v21は各cNを`{Q,facts}`とし、同じ請求項内の実際の引用位置をQへ一度だけ記述する。
Qは部品名の正規化辞書ではない。AIが記述した原文・句範囲・必要な前後文脈を厳格に
照合し、各命題の引用はQのindexを参照する。他請求項の引用、原文不在、未使用や
同一位置の重複登録を拒否する。Qそのものも実wireの64,000 bytes上限に含む。
Oは`[selection,extent,polarity,guard,context]`の5要素配列とし、名前の反復だけを
省く。長さ・順序を検証し、各index/nullを旧5項目へ復元する。条件は4番目、否定は
3番目で、項目省略や根拠の自動補完は認めない。

flatなfactsのRは原文の句番号で、実際のm引用との交差とRの非減少を検証する。
空行を数える二重管理をなくすが、RやQから不足した意味は生成しない。loopも当該
請求項のQと明示的Rを用い、F外のloop IDとF内の引用indexを区別する。
展開中間表現の大きさと実wire容量を区別し、内部witness32,000 bytes、1用語80文字、
1命題12句、1原文96命題と既存の意味検証を維持する。旧v20の入口はそのまま保持する。

読取りでは部品の保有とその機能を別に確認し、後置された機能主体、制御主体と状態の
主体、維持状態の全体、ORの共通条件、経路の後半を省略しない。架空の主体・保有・
機能例は形式の説明に限り、実公報の正解を埋め込まない。圧縮された失敗応答は
容量分析の資料であり、修復して合格回答として採用しない。

v22は引用の識別子を`q17|first-last:原文`のように宣言し、命題から`"q17"`を
完全一致で参照する。曖昧な引用objectには`id`を明記する。Q配列の何番目かを
モデルに数えさせず、宣言の順序からIDを推測・補正しない。重複ID、未宣言参照、
未使用・同一位置の重複、別請求項参照は拒否する。旧v21の整数参照は保持し、
失敗済みの応答を新形式へ修復して採用しない。

全句を読む複数回の確認と、最終出力の順序は別である。原文の後方にある保有命題を
先頭へ移動せず、各命題を実際の作用句Rの順に出力する。hasのaは部品名ではなく
保有を表す原文を引用する。IDの正しさだけでは未抽出・主体・条件・経路の品質を
証明できないため、既存の原文QAと全件比較・帳票確認を引き続き必須とする。

受動的な配置は、原文に明記された名詞句＋`に設けられた／に設けられる`を
既存の`is_state`でそのまま表す。外側・二点の間を別部品の内側や上流へ置き換えない。
先行する動作や条件節を配置句へ取り込まず、条件付きの前提を独立した状態と
断定しない。部品名が配置句の後に続く場合も、主体と原文位置の検証を維持する。
