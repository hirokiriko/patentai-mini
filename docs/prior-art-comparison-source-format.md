# 比較原文の可逆な抽出形式

原文の引用と意味を別々に検証する。引用の位置が正しくても、主体、否定、条件、
経路、選択関係が正しいとは限らない。実AIの品質判定には原文との照合が必要である。

source wire v13は、完全な抽出を既存の32,000 UTF-8 bytes以内で表すための形式である。
フィールド名と固定enumを可逆に符号化し、各命題とその根拠は独立して保持する。
`p3:赤色弁`は当該請求項の入力part 3にある完全一致引用を表す。最初のコロンだけで
分割し、指定partに一意に存在しなければ拒否する。同じpart内の反復やpartを跨ぐ引用は、
`["q",quote,before,after,edge]`で原文の隣接文脈を明示する。別の位置への探索や補正はしない。

復号後は従来の厳密schema、請求項・sourceの一致、完全claimのbasis、80文字のterm、
guardの包含、演算子の根拠、必須閉路などを検証する。全件を不確実にしたり、
必要な命題を省略したりすることで容量を満たしてはならない。

同時開動作、いずれか一方の開動作、実行、停止、受動的な給電終了を区別する。
給電終了では根拠のない遮断主体を補わない。これらの述語を一般的な開動作や集合所属へ
読み替えず、条件・否定・参照関係についても既存の保守的な比較を維持する。

実行内witness v2は、同じ意味の接頭部と位置情報の重複を減らす。元の順序、claim番号、
全bindings、operators、routeFrameをv1へ完全復元できる。v1の展開も保持し、
再符号化が一致しない余分な辞書や非標準のtupleは拒否する。内部上限は16,000 bytesのまま。

target入力のdescriptor v2は主語とbasisの辞書を使用する。各行のID、claim番号、
basis、kind、subjectを損失なく復元でき、上限6,000 bytesを維持する。
target回答のv1、保存結果のv1、再表示・PDF・CSVの読込形式は変更しない。

架空入力の往復・境界・統合テストは接続と容量の確認であり、実AI品質の合格や
本番での利用確認を代替しない。
