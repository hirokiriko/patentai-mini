# 指定文献比較の実務者評価

Issue #150の評価開始準備。実務者の評価回答と、#152の全件品質研究は別工程。
現在は準備中であり、この文書だけで配備・実AI成功・評価開始可能を示さない。

## 今回修正する停止原因

保持した原文・source応答・review応答を照合すると、同じ条件付き動作をsourceの一方だけが能力として分類していた。
その1命題を参照する候補観察・共通点・差分の3項目がcontext不一致となり、coverage検査が保存を拒否した。
review側の動作分類と拒否は妥当である。sourceの指示とschema説明を、明示条件下の動作と明示された能力・機能を区別する既存review契約に揃える。
原回答、validator、decoder、入力、成功判定は変更しない。指示修正の有効性は、修正後の実AIと原文照合で確認する。

## 代表例（実行前に固定）

| 役割 | 文献 | 選択箇所 |
| --- | --- | --- |
| 基準 | [JP2017-190074A](https://patents.google.com/patent/JP2017190074A/ja) | 請求項1 |
| 候補 | [JP2018-140722A](https://patents.google.com/patent/JP2018140722A/ja) | 請求項2と、その引用元の請求項1 |

既存の公開原PDFと原ページ照合済み請求項テキストを使う。引用元を省略せず、公開時の文献種別・版を維持する。
一般的な精度保証ではなく、この代表例の追跡性と有用性を評価する。

確認点は次のとおり。

- 基準の第1運転モード、圧縮機起動後、所定期間、大きい開度の維持が残るか。
- 候補の第2運転モード、低回転時の閾値条件、逆圧防止が区別されるか。
- 室外膨張弁と第1開閉弁を混同せず、両方を開くことと請求項2の同時性を保つか。
- 請求項2から請求項1への依存と、各判断の原文位置を追跡できるか。

## OWNERによる操作実演

既存OWNER限定の固定URLへ通常の認証で入る。認証情報は他者へ共有しない。
原文・文献番号・選択請求項を確認して比較を1回開始し、処理中は再送しない。
成功した保存結果を表示し、原文参照・比較理由・差分・未確認事項を確認する。
その結果を再表示し、同じ保存結果のPDFとCSVを取得する。再表示・帳票取得では新しい比較を開始しない。

失敗表示や結果不明を成功・候補なしに読み替えない。旧正常結果を保持し、失敗した操作を再送しない。
受入後の案内には配備commit、固定URL、保存結果の識別子、成果物の対応、実測費用と留保を追記する。
比較ONと現行利用条件を実確認するまで、評価開始準備完了としない。

## 実務者へ渡すものと質問

公開可能な原文・出典、比較結果、同じ結果のPDF/CSV、短い操作手順を一組にする。
内部監査原本・認証情報・非公開案件を成果物へ混入させない。
実務者にはOWNERの操作実演と成果物のレビューを依頼する。

| 評価項目 | 記入してもらう内容 |
| --- | --- |
| 見逃し | 重要な共通点・差異・条件の見逃しと原文箇所 |
| 不要候補 | 不要・過大な指摘とその理由 |
| 確認時間 | 原文確認から所見までのおおよその時間、比較支援で減った／増えた作業 |
| 説明 | 比較理由・引用・未確認事項の理解しやすさ、不明な記述 |
| 帳票 | PDF/CSVで判断・共有しやすい点、足りない情報 |

## 対応範囲と制約

指定文献・指定請求項の比較支援であり、文献探索の網羅性や法的判断を保証しない。
条件・引用・構造・意味の検査で停止することがある。旧SDK失敗の一部は原応答不足で直接原因未確定のまま保持している。
旧架空成功例は接続・保存・再取得確認に再利用できるが、実務的有用性の証明ではない。
自動取得、通知、外部顧客アカウント、専用試用環境、全24文・4組の全件品質研究はこの評価の前提ではない。
通常比較の金額累計を自動遮断する機能はない。引渡し時に許可されたOWNER利用枠・費用確認・停止方法を明記する。
