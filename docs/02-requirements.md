# 02 Requirements

## スコープ内
1. ユーザーの特許案ファイル受領
2. 特許案の構造解析
3. J-PlatPat 用検索式生成
4. J-PlatPat 検索結果ファイル受領
5. 既存特許群の解析
6. 一致候補・差分候補の抽出
7. レポート生成

## スコープ外
- J-PlatPat の自動スクレイピングや自動ログイン
- 出願書類の正式作成
- 法的鑑定書の生成
- マルチテナント・厳格認可

## 機能要件
### FR-01 特許案アップロード
- PDF / DOCX / TXT を受け付ける
- 文書からタイトル、要約、請求項、課題、効果を抽出する

### FR-02 要素分解
- 独立請求項 / 従属請求項を識別する
- 各請求項を構成要素へ分解する
- 要素間関係をラベル化する
  - 例: 構成、条件、入出力、制御、効果

### FR-03 検索式生成
- キーワード案、同義語案、上位概念、下位概念を出す
- 広め / 中庸 / 狭め の検索式を作る
- 検索式の意図を説明する

### FR-04 既存特許取り込み
- J-PlatPat 由来の CSV を取り込む
- 必要なら公報 PDF や追加テキストも別途取り込めるようにする
- global公報corpusを公開番号、出願番号、発明名称で明示的に検索し、選択した公報を案件の比較対象へ追加できる
- global公報corpusの検索は初期表示や入力中に自動実行せず、ユーザーの検索操作でのみ実行する
- 案件へ追加した公報は比較用snapshotとし、global rowの更新・削除を自動反映しない
- 同一案件・同一公開番号の再追加は新規、更新、変更なしを判定し、比較対象が変わった場合だけ既存分析結果を無効化する

### FR-05 類似分析
- 文字列一致
- ルールベースの要素一致
- 埋め込みベースの意味類似
- 請求項構造比較

### FR-06 レポート
- 危険文献 Top N
- 一致要素、差分要素、未比較要素
- なぜ危険と見たかの説明
- 次に確認すべき論点

### FR-07 国内優先権主張出願モード（公開前ベース出願 + 新規事項）
- 案件作成時に「公開前の出願済み特許に新規事項を付け加える特許か」を Yes/No で選べる
- Yes の場合は次の 2 ファイルを別々に受け付ける
  - ベース出願（公開前の自身の出願済み特許）
  - 新規事項（追加したい部分）
- 任意項目としてベース出願番号（例: 特願 2026-40454）をメタ情報として保存する
- AI がベース出願 + 新規事項を読み込み、両者を統合した「新しい発明全体の明細書テキスト」を生成する
- 統合結果を通常の特許案ドラフトとして扱い、FR-02〜FR-06 の既存フロー（請求項抽出 → 検索式生成 → 先行技術取込 → 重なり分析）に合流させる
- ベース出願は自身の先願であり、本人が出願人である限り 29 条の先行技術にはならない（公開前のため）。一方、29 条の 2（拡大先願）の対象となり得る点は念頭に置くが、本 PoC では機械判定はせず、ユーザーが手動で除外できれば良いとする
- 法的文言（補正要件 17 条の 2 第 3 項、新規事項追加禁止）は本 PoC のスコープ外。ユーザーへの警告表示までに留める

### FR-08 出願後ウォッチングMVP

- 案件ごとにウォッチの有効／無効と実在する監視開始日を保存する
- ユーザーの「今すぐ監視」という明示操作時だけ、取り込み済みglobal公報corpusを差分処理する
- 初回は監視開始日以降、2回目以降は前回成功runの固定cursorより後かつrun開始時の固定upper cursor以下だけを対象とする
- 新着公報を決定的な語彙重なりで最大100件に絞り、既存分析engineへ渡す文献を最大20件に制限する
- 同一公開番号と同一content digestのfindingを再取込や再実行で重複させない
- AIが利用できない場合は決定的fallbackを保存し、人による確認が必要な候補であることを明示する
- 最新run、過去run、新着finding、確認状態、UTF-8 CSV、browser印刷用HTMLを提供する
- 初期表示では監視runやcorpus検索を実行せず、watch状態取得だけを行う
- 出力は調査・比較・論点整理の支援に限定し、法的判断を表示しない
- 詳細契約は[出願後ウォッチングMVP仕様](10-patent-watching-mvp-spec.md)に従う

## 非機能要件
- PoC なので可用性・水平分散は不要
- 単一ユーザー想定でよい
- ローカル実行または小規模サーバーで十分
- 解析再現性のため、プロンプト・モデル・閾値は保存する

## データ要件
### 入力
- 自身の特許案
- J-PlatPat 検索結果 CSV
- 必要に応じて個別公報 PDF
- 必要に応じてglobal公報corpusから明示選択した公報

### 中間データ
- 要素抽出 JSON
- 検索式候補 JSON
- 特許文献正規化 JSON
- 類似度計算結果 JSON

### 出力
- サマリレポート
- 要素対応表
- 危険文献ランキング
- 出願後ウォッチングの新着確認候補、run履歴、CSV、印刷用HTML

## 受け入れ基準
- 同じ入力に対して、少なくとも主要な要素分解結果が安定する
- 検索式がノイズだらけでなく、人間が J-PlatPat に投入可能
- レポートを見て、どの請求項が危ないか追跡できる
