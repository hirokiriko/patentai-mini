# 02 Requirements

## スコープ内
1. ユーザーの特許案ファイル受領
2. 特許案の構造解析
3. J-PlatPat 用検索式生成
4. J-PlatPat 検索結果ファイル受領
5. 既存特許群の解析
6. 一致候補・差分候補の抽出
7. レポート生成

## スコープ外
- J-PlatPat の自動スクレイピングや自動ログイン
- 出願書類の正式作成
- 法的鑑定書の生成
- マルチテナント・厳格認可

## 機能要件
### FR-01 特許案アップロード
- PDF / DOCX / TXT を受け付ける
- 文書からタイトル、要約、請求項、課題、効果を抽出する

### FR-02 要素分解
- 独立請求項 / 従属請求項を識別する
- 各請求項を構成要素へ分解する
- 要素間関係をラベル化する
  - 例: 構成、条件、入出力、制御、効果

### FR-03 検索式生成
- キーワード案、同義語案、上位概念、下位概念を出す
- 広め / 中庸 / 狭め の検索式を作る
- 検索式の意図を説明する

### FR-04 既存特許取り込み
- J-PlatPat 由来の CSV を取り込む
- 必要なら公報 PDF や追加テキストも別途取り込めるようにする

### FR-05 類似分析
- 文字列一致
- ルールベースの要素一致
- 埋め込みベースの意味類似
- 請求項構造比較

### FR-06 レポート
- 危険文献 Top N
- 一致要素、差分要素、未比較要素
- なぜ危険と見たかの説明
- 次に確認すべき論点

## 非機能要件
- PoC なので可用性・水平分散は不要
- 単一ユーザー想定でよい
- ローカル実行または小規模サーバーで十分
- 解析再現性のため、プロンプト・モデル・閾値は保存する

## データ要件
### 入力
- 自身の特許案
- J-PlatPat 検索結果 CSV
- 必要に応じて個別公報 PDF

### 中間データ
- 要素抽出 JSON
- 検索式候補 JSON
- 特許文献正規化 JSON
- 類似度計算結果 JSON

### 出力
- サマリレポート
- 要素対応表
- 危険文献ランキング

## 受け入れ基準
- 同じ入力に対して、少なくとも主要な要素分解結果が安定する
- 検索式がノイズだらけでなく、人間が J-PlatPat に投入可能
- レポートを見て、どの請求項が危ないか追跡できる
