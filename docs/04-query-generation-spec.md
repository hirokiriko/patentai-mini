# 04 Query Generation Spec

## 目的
特許案から、J-PlatPat で実用になる検索式を生成する。

## 入力
- 発明の名称
- 要約
- 独立請求項
- 従属請求項
- 解決課題
- 作用効果

## 出力
- broad_query
- balanced_query
- narrow_query
- keyword_groups
- excluded_terms
- rationale

## 生成手順
1. 独立請求項を主軸にする
2. 構成要素を分解する
3. 必須要素 / 任意要素 / 効果語を区別する
4. 同義語・言い換えを展開する
5. ノイズ語を除外する
6. 広狭 3 段階の検索式を作る

## 検索観点
- 課題起点
- 手段起点
- 効果起点
- 構成要素起点
- 分類起点（IPC/FI/Fターム は人手補完を許容）

## J-PlatPat で意識する点
- 論理式では、検索キーワードと検索項目タグを `/` で区切る方式がある。例として、請求の範囲に「クラウド」を含む検索は `クラウド/CL` と記述できる。citeturn1search6
- ワイルドカード `?` を使った表記や、近傍検索の指定もヘルプで案内されている。citeturn1search6
- 人名検索では、表記揺れ対策としてスペース有無を考慮した検索が FAQ で案内されている。citeturn1search4

## 出力フォーマット例
```json
{
  "keyword_groups": {
    "core": ["要素A", "要素B"],
    "synonyms": ["言い換えA", "言い換えB"],
    "effects": ["高速化", "省電力"]
  },
  "broad_query": "...",
  "balanced_query": "...",
  "narrow_query": "...",
  "excluded_terms": ["汎用語A"],
  "rationale": [
    "独立請求項の必須要素を優先した",
    "作用効果語は広め検索にのみ残した"
  ]
}
```

## 失敗パターン
- 発明の説明をそのまま長文で検索式化する
- 効果語だけで検索してしまう
- 独立請求項の必須制約を落とす
- 同義語展開が過剰でノイズ化する
