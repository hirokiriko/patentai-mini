# Patent Prior-Art Check PoC

個人利用向けの PoC です。目的は、**ユーザーがアップロードした自分の特許案**を起点に、J-PlatPat 用の検索式生成、検索結果の再アップロード、既存特許との**請求項・構成要素レベルの重なり検出**、および**リスク信号の早期把握**までを一連で扱うことです。結果は調査・比較・論点整理の支援であり、法的判断を代替しません。

## 目標
- 特許案から検索語・同義語・観点語を抽出する
- J-PlatPat で使う検索式案を生成する
- ユーザーが J-PlatPat で検索し、結果を CSV 等で持ち帰る
- 持ち帰った既存特許群を解析し、自身の請求項との重複要素を可視化する
- 重複候補、差分候補、要確認点を報告する

## 非目標
- 弁理士・弁護士レベルの法的判断の代替
- 本番レベルの堅牢性、強固な認証認可、高度な監査ログ
- J-PlatPat の自動操作

## PoC の基本方針
- **人間が J-PlatPat を操作する外部工程**を前提とする
- AI は検索式生成と比較分析に集中する
- DB は Postgres、ORM は Drizzle を使用する
- AI provider は Google、OpenAI、Azure OpenAI に対応する
- Azure Container Apps を現行の主要deploy経路とする

## 主要フロー
1. ユーザーが自分の特許案をアップロード
2. AI が請求項・課題・作用効果・構成要素を抽出
3. AI が J-PlatPat 用検索式を複数案生成
4. ユーザーが J-PlatPat で検索し、検索結果をダウンロード
5. ユーザーが結果ファイルを再アップロード
6. システムが既存特許を解析し、重複候補・差分候補を算出
7. 調査支援レポートを返す

## 開発運用

開発タスクは GitHub Issue を入口とし、各実装Issue本文をタスク、必須仕様、受入条件の唯一の正本とします。Issue／PRは進捗、検証、再検証、引継ぎの正本です。Issue本文は、それだけで担当Codexが開始からPR作成まで完遂できる自己完結した正式指示にします。公開GitHubへのリンクは補足・証拠に限り、必須指示の代わりにしません。開始指示は原則「Issue #Nを進めて」だけでよく、チャットや過去会話を必須仕様にしたり、ユーザーに長文promptの中継を求めたりしません。

不足・矛盾・判断待ちはIssue／PRへ記録して停止ラベルを付け、Cloud／Local／Verifier間の修正要求、検証、再検証、引継ぎもGitHub上で完結させます。現行状態は関連Issue／PR、CI、最新のdefault branchで確認してください。
